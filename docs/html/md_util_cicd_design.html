Directory Tree

Directories Descriptions

<GDAM_DATA>/work/public/sys/cicd/<Project-Name> This is the project directory. User-defined scripts are under this directory

<GDAM_DATA>/temp/public/sys/cicd/ws/<Project-Name> This is the project directory under workspace folder
<GDAM_DATA>/temp/public/sys/cicd/log This is the log directory

Project Dependency

The optional file depend.txt can be defined under the project directory <GDAM_DATA>/work/public/sys/cicd/<Project-Name>. Each line in depend.txt is a project name which is a dependent item of such project under that directory.

Stages

User-defined scripts are divided to 3 steps.

Stages Descriptions Windows Linux
Code Fetch source code code.bat code.sh
Build Build project build.bat build.sh
Deploy Deploy in local and/or remote machine deploy.bat deploy.sh

Build step can include building debug version, testing, building release version, and packing for publishing.

The return value of script is 0 when it runs successfully. If the source code is not changed, 1 should be returned in code script. Non-zero value indicates some errors are occupied.

The optional scripts vars.bat (windows) and vars.sh (linux) can be defined under the script directory of project in local machine. They will be called before other scripts if they exist. The format of such scripts is shown as follows:

vars.bat:
@SET XXX=XXX
...
vars.sh:
export XXX=XXX
...

The optional scripts vars.bat (windows) and vars.sh (linux) can be also defined under the directory <GDAM_DATA>/work/public/sys/cicd. They will be called before other scripts in project directory if they exist.

Some scripts like _remote-deploy.bat (windows) and _remote-deploy.sh (linux) can also be defined under the script directory of project in local machine. They will be copied to remote machine and be executed for deployment.

All processes created by ssh (remote script) will be killed after the end of session under windows. So use schedule task to start the RC scripts (delay-task.bat).

Environment Variables

WORKSPACE_ROOT Specify the workspace directory for the root of projects
